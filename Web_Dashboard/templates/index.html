● LIVE — DEPLOYED
Regime-Switching Market-Neutral System
Statistical Arbitrage + Funding Rate Carry, orchestrated by a macro regime detector
Concept

A regime detector runs hourly and decides which of two independent, market-neutral strategies gets capital: Statistical Arbitrage when ETH shows mean-reverting microstructure, Funding Rate Carry when volatility spikes or no clear signal exists. Neither strategy takes directional exposure to crypto prices.

Layer 0 — Regime Detector

Research → Data → Features

Two-level filter: BTC/USDT realized volatility (24h rolling, annualized) captures systemic stress; ETH/USDT Hurst Exponent (100h rolling) + ADX (14-period) capture whether the DeFi/L2 ecosystem ETH anchors is currently mean-reverting or trending — a more relevant proxy for AAVE/ETH-style pairs than BTC alone.

Training — rule-based, not ML

Thresholds calibrated on percentile analysis of 1 year of hourly data rather than arbitrary values: BTC vol > 0.60 → HIGH_VOL · ETH Hurst > 0.47 & ADX > 28 → TRENDING · ETH Hurst < 0.43 & ADX < 36 → MEAN_REV · else NEUTRAL.

Layer 1 — Statistical Arbitrage

Research → Data → Features

Pairs trading: trade the mean-reverting spread of two cointegrated assets instead of predicting direction. Pair selected via Engle-Granger cointegration (p<0.05) + Hurst (<0.5) + out-of-sample ADF. Hedge ratio computed via Rolling OLS (200-candle window) rather than a static mean-price ratio, to avoid stale-ratio drift.

Training — LightGBM meta-labeling

Labeled via Lopez de Prado's Triple Barrier Method (TP: Z→0, SL: |Z|≥4, 24h limit). The model acts as a gatekeeper — only enters above 60% confidence.

Backtest — an honest negative finding

Re-tested 6 months later on refreshed data: raw win-rate dropped to 36.78%, ML-filtered backtest PnL turned negative (-6.74%). Rather than discarding the result, this directly motivated building the Regime Detector instead of trusting one static backtest indefinitely.

Deployment → Oversight

Live on Binance Demo Futures, 15m cycle. Three independent stop-losses: Z-Score (|Z|≥6), PnL (-5%) — added after observing a live divergence where the Z-Score improved while PnL kept deteriorating from imperfect hedge coverage — and a 48h time barrier. Position recovery via live API query survives service restarts. Weekly re-scan across 11 candidate pairs.

Layer 2 — Funding Rate Carry

Research

Delta-neutral: Long Spot + Short Perpetual, harvesting the funding rate paid every 8h by leveraged longs. Placed in HIGH_VOL/NEUTRAL rather than competing with StatArb for MEAN_REV — leverage demand (and funding) typically rises, not falls, during stress, making the two strategies structurally complementary.

Training — fee math before code

Round-trip cost (both legs, standard fee tier): 0.30%. Selection filter: 30d APR > 4%, positive-payment consistency > 60%, current rate > 0.

◐ PIVOTED
Polymarket 15-Minute Binary Contracts
BTC Up/Down prediction markets — mathematically unviable spread
Research

Pivoted from BTC 4H after finding it too noisy — Polymarket's binary "Up or Down" contracts offered a mathematically clean label (close[t+15] > close[t]), $1.00/$0.00 settlement, zero liquidation risk, and 0% execution fees. Traded on the Polygon network as a prediction market rather than a leveraged derivative.

  • Trading Horizon: ultra-short term (15m) to intraday, daily close 4PM ET.
  • Underlying Driver: mathematical probability of short-term directional movement.
  • Primary Quantitative Risks identified upfront: phantom liquidity, API architecture constraints (Event ID vs Market ID), microstructure risk from empty L2 orderbooks on directional algorithms.
Data
  • Market Data: Polymarket Gamma API (metadata, market status, aggregated "web liquidity") + CLOB API (L2 orderbook depth, Best Bid/Offer).
  • Execution Data: spread endpoint, L1 imbalance (top-of-book volume).
  • Underlying Data: real-time BTC prices for ML inference.
Features

Short-term OHLCV (1m/15m) engineered into high-frequency momentum and volatility contraction predictors.

Training

Phase 1 — Probability Prediction: LightGBM optimized for binary classification, 15m horizon to next daily close.
Phase 2 — Confidence Thresholding: Random Forest meta-labeling, dynamically thresholding entries against Polymarket's own live share price (execute only if model confidence > market ask price).

Deployment

Diagnostic scanners (poly_scanner.py, top_markets.py) deployed to scan the CLOB API in real time ahead of full live deployment.

Live Diagnosis — the market itself was the problem

Finding 1: discrepancy between the Web UI's aggregated liquidity figure and the actual CLOB API orderbook. Finding 2: lack of institutional market makers on pure short-term directional contracts.

The model itself was not the failure point; the market's execution structure was. Pivoted to Statistical Arbitrage on Binance Futures, where spreads are a negligible fraction of position size.

◐ PIVOTED — ORIGIN
BTC/USDT 4H Directional Swing Trading
Where it started — XGBoost + meta-labeling on 4H BTC
Research
  • Market Characteristics: 24/7/365 trading environment, heavily retail-driven, distinct cyclical regimes.
  • Trading Horizon: swing trading.
  • Underlying Drivers: funding rates, on-chain flows, macroeconomic cyclicality.
  • Execution & Capital: €100 initial budget, forward-tested via Binance Testnet.
  • Primary Quantitative Risks: look-ahead bias, overfitting (curve-fitting) — flagged before any model was trained.
Data
  • Market Data: OHLCV.
  • Alternative Data: Funding Rate, Fear & Greed Index.
  • Macroeconomic Data: DXY (US Dollar), equities (via yfinance).
  • Excluded: Open Interest — historical data unavailable at the required granularity.
Features

9 raw inputs engineered into 15 quantitative predictors: stationary transformations, volatility metrics, relative distances.

Training

Phase 1 — Primary Model (Directional): 4H timeframe predicting T+24H (rolling window for time diversification). XGBoost selected over LightGBM after purged cross-validation. Hyperparameters tuned via Optuna (TPE algorithm, Median Pruner).

Phase 2 — Meta-Labeling: Random Forest Classifier (n_estimators=200, max_depth=5, class_weight='balanced'). Triple Barrier setup: PT = 1.5× volatility, SL = 1.0× volatility, Time Limit = 24h. Break-even (1.5:1 R/R) required >40.0% precision.
